# Evidence-bound academic writing

Bounded OpenCode R14 adaptation of K-Dense scientific-writing 2.1 and its writing/evidence guidance. The original files and exact adaptation comparison live in this round's upstream/ and records/ directories. Preserve LICENSE.md. This candidate is not a global installation or a submission approval.

Use the existing author as the single writer when the primary delegates academic content. Researcher/primary owns scientific decisions; analyst owns derived results; document owns source retrieval and identity. Return only consequential gaps through the primary. Do not execute shell commands, delegate, change models/permissions or invoke other skills to bypass the role's limits.

## Start at the requested scope

Read the exact source package and requested passage/version. Establish what is available, its confidentiality, language, audience, accepted methods/claim limits and allowed output path. Reuse an existing evidence table; do not create a complete manuscript registry for a short passage. Missing venue/funder is not a blocker for neutral academic prose or a general proposal narrative. Do not assume Nature, NSF, NIH or NSTC requirements, article structure, page limits, deadlines or templates.

For a public or explicitly authorized internal draft, distinguish agent-inspected support from human-verified support. Record who actually checked what; never mark a human check complete for the agent. Human scientific approval, disclosure decisions and submission remain separate when the actual task requires them. This public bounded check is not a formal confidential review or an approved manuscript.

Preserve originals and use derived copies unless an exact revision is authorized. Never send unpublished manuscripts, confidential reviews or restricted data outside the approved boundary. Existing authorization persists; ask only about an unresolved issue that changes current correctness, scientific interpretation or permission, and continue independent work.

## One writing flow

1. Build a compact outline from inspected support: purpose → method/context → result → bounded interpretation. Use only the structure the passage needs. A source being found or downloaded does not establish it was read or supports a claim.
2. Draft factual claims from evidence with locators. Keep cited prior work, previously executed analysis, present inspection, interpretation and proposed work distinguishable. Never invent data, units, denominators, uncertainty, citations, methods, approvals, funding or completed actions.
3. Revise paragraph logic before polishing sentences. Repair misplaced purpose/results/limitations and ambiguous referents. If structure needs new science, return the gap; do not conceal it with fluent language.
4. Polish into neutral academic English unless a real target style is supplied. Use consistent terms and direct sentences. Preserve negation, modality, uncertainty, direction, comparisons, numbers and citations. Do not add causal, significant, novel, robust, validated or universal claims without support. Scientific constraints take priority over elegance.
5. For Chinese-English transfer, compare propositions, not just words: actor/system, measured versus assumed quantity, direction, units/denominator, uncertainty/negation, causal strength and completed versus proposed tense. A short terminology table is sufficient when useful. Back-translation alone is not proof of fidelity.
6. Read back the actual saved revision. Reconcile affected numbers, source locators, figures/captions and limitations. Preserve versions and a short change map only when needed to make revisions reviewable. Recheck changed or suspect claims; do not rerun analyses or a whole pipeline merely because prose changed.

## Responses and proposal paragraphs

For a response, keep the comment and reply tied to the exact changed passage/version. Describe completed edits only after inspecting them. Say explicitly when work is proposed or not performed. A comment-level response needs no invented editorial decision, reviewer identity, page/line number, acceptance result or full response package.

For a proposal, use the same evidence → gap/question → proposed approach → observable outcome/limitation logic. Distinguish public literature/reference results from the applicant's preliminary data. State feasibility only at the tested level. Do not invent sample sizes, milestones, budgets, achievements, partners or funding rules. If a retained scientific aim needs new assumptions or design, return it to the primary/researcher; do not manufacture a completed study to strengthen the application.

## Checks and handoff

Return the actual path/version, claims and support inspected, edits and checks performed, remaining limits and any required scientific handoff. This guidance itself performs no computation, source lookup or independent audit. The primary can run already-authorized mechanical comparisons using existing tools. Upstream optional CLIs, complete registries, formatting, automatic citations to a skill paper and submission steps are not imported into this bounded candidate.

Respect HumanReview and the existing authorized_review_chain when an independent final audit is triggered. A self-check, skill discovery or fluent file is not independent scientific validation. Do not add another full review simply because a critic exists.
